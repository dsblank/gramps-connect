Layer 2 — local-first cache

Objects fetched once from a real gramps-web-api instance via the fast, keyset-paginated POST /api/<type>/query/ endpoints, mirrored into a WASM SQLite table (one per object type -- see the sidebar) using the same secondary columns Gramps already flattens server-side, and persisted to OPFS.

The first page sets the scrollbar's bounds (its count: true response gives the total row count); every later page fills that view's local cache in the background, in the same order the table below uses. Only the rows actually scrolled into view are ever queried from the local cache or rendered as DOM nodes. Switching views doesn't lose what's already loaded -- each keeps its own cache.

exists(...)/count(...) -- a Collection's cardinality, e.g. how many events a person has -- work as a where_expr filter independent of what's selected/ displayed; try the example buttons below (People view only), or type your own.
