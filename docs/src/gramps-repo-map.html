Repo map · ~/gramps

How the Gramps codebases fit together

Six repositories on disk, and three kinds of relationship between them: a Python import, a shared REST API, and two Gramps addons that connect Desktop to a server — one continuous, one run on demand.

Python import — compile-time library dependency
REST API — live HTTP request/response, from a frontend
Desktop ↔ server sync, via an addon — solid = continuous (GrampsWebApiDb), dashed = run on demand (GrampsWebSync)
plugin containment — installs into the host process

Repository index

Same six nodes, with the one-line role each plays.

RepoPathRole
gramps ~/gramps/gramps Desktop app and the gramps.gen core library — data model, DB backends, import/export, report engine — that every other project here builds on.
gramps-web-api ~/gramps/gramps-web-api A Flask REST API that imports gramps.gen directly and opens a family tree over HTTP: search, editing, media, DNA, AI chat, and the transaction-history feed live sync depends on.
gramps-web ~/gramps/gramps-web The production web client — browse and collaboratively edit a tree from any device. Lit-based; a REST client of gramps-web-api.
gramps-connect ~/gramps/gramps-connect A second web frontend built for instant local browsing and live multi-user editing. Same REST surface as gramps-web, plus fast /query/ endpoints. Runs two ways: hosted (deploy/) against a shared gramps-web-api server for real collaboration, or standalone as a single-user desktop app that bundles its own gramps-web-api + SQLite into one process.
GrampsWebApiDb ~/gramps/addons-source/GrampsWebApiDb A plugin for gramps that makes a gramps-web-api server usable as Desktop's live database: reads come from a local SQLite mirror kept current by polling the transaction-history feed, writes push straight back to the server.
GrampsWebSync ~/gramps/addons-source/GrampsWebSync A Gramps tool, run on demand, that diffs a local tree against a gramps-web-api server and reconciles the two — bidirectionally by default, or resetting one side wholesale. Talks to the same REST API as the web frontends; unlike GrampsWebApiDb, nothing stays open or polls between runs.
Two addons exist for a reason: GrampsWebSync runs when you ask it to, diffs both sides, and reconciles them — the way syncing has always worked here. GrampsWebApiDb is the newer alternative: open the tree and it stays current in both directions, continuously, without a manual step.
